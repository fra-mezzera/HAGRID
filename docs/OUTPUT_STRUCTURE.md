# HAGRID output directory reference

This document describes the file and directory conventions used by HAGRID. Paths are relative to the repository root. Run-specific directories are created when the corresponding processing stages are executed.

## Modules 01–03

```text
output/
├── 01_Mtx_activ/                           # Module 01 activity transition matrices
├── 01_Mtx_places/                          # Module 01 location transition matrices
├── 01_activity_profiles/
│   ├── yearly_profiles/<region>/           # annual individual profiles
│   └── weekly_profiles/<region>/           # selected-week individual profiles
├── 01_profiles_Pics/                       # plots
├── 01_diagnostics/                         # checks and case metadata
├── 02_household_activity_profiles_Xls/      # generated household profiles
├── 02_base_consumption_Xls/               # conventional load time series/tables
├── 02_base_consumption_Pics/              # appliance/household plots
├── 03_additional_consumption_Xls/         # additional loads, statistics, DHW & EV metadata
└── 03_additional_consumption_Pics/
    └── <n>_households_<region>/             # additional-load plots
```

**Dependencies:** Module 02 reads Module 01 weekly profiles. Module 03 reads Module 02 profiles and conventional loads. Module 04 reads Modules 02–03 demand outputs. Do not delete intermediate tables unless you can rebuild them.

## Module 04: run-specific output trees

The base path includes a grid family (e.g., `urban`, depending on `LV_ARCHETYPE`) and a generated experiment/run identity. All branches in the example below are *templates*: the actual names are generated by the notebook and are recorded in the manifest.

```text
output/
├── 04_PV_EE_profiles_Xls/
│   ├── GME_EE_prices_10min/
│   └── PV_10min_weeks/
│
├── 04_HGD_res_xls/<grid_group>/
│   └── EXP_<experiment_id>/<run_folder_name>/
│       └── ... per-run spreadsheets
├── 04_HGD_res_py/<grid_group>/
│   ├── _shared/                      # technology allocation/column mapping shared files
│   └── EXP_<experiment_id>/<run_folder_name>/
│       └── ... per-run Python/pickle objects
├── 04_HGD_res_pics/<grid_group>/
│   └── EXP_<experiment_id>/<run_folder_name>/
│       └── ... figures
│
├── 04_HGD_for_PF_Py/<grid_group>/
│   ├── _catalog/
│   │   ├── HAGRID_run_manifest.csv
│   │   └── HAGRID_run_manifest.xlsx
│   ├── IDX_REAL_BY_SEASON_<dataset_tag>.pkl.gz
│   └── EXP_<experiment_id>/<run_folder_name>/
│       └── ... LV/PF-interface exports
│
├── 04_HGD_rb_cache/<grid_group>/
│   └── <experiment_uid>/<revision_uid>/<context_uid>_<parameter_signature>/
│       └── ... rule-based reference profiles and metadata
│
├── 04_HGD_cmp_multi_runs/<grid_group>/
│   └── EXP_<experiment_id>/REV_<run_revision>/
│       ├── ... experiment summaries
│       ├── soc_compare/<case_A>__VS__<case_B>/
│       └── <comparison_type>/<optional_comparison_tag>/
│
├── 05_Kerber_grid_archetypes_Py/
│   ├── kerber_urban_grid_kabel_1.json   # selected urban Kerber blueprint (when provided)
│   └── ... other supported archetype JSON files
│
└── 05_Power_Flow_Xlsx/<grid_group>/
    └── EXP_<experiment_id>/<run_folder_name>/
        └── ... optional PF-calibrated line-limit inputs
```

**Run identity:** The notebook constructs a `run_label`, a deterministic short `run_uid` (`R_...`) and a `run_folder_name` in the form `<run_label>__<run_uid>`. The identifier includes a canonical representation of model settings and `RUN_REVISION`; a run from a new revision need not reuse an old path. Use the **manifest** to find runs rather than manually rebuilding folder names.

**Kerber blueprint prerequisite:** Module 04 loads pre-generated LV grid-archetype JSON files from `output/05_Kerber_grid_archetypes_Py/` (the location retained for compatibility with the current code). For `LV_ARCHETYPE = "kerber_urban_grid_B"`, it expects `kerber_urban_grid_kabel_1.json`. Although this directory is under `output/`, the blueprint JSON is an **input prerequisite** for Module 04, not an output that Module 04 regenerates. The example JSON files provided in this repository may be reused for their corresponding archetypes; verify that the chosen blueprint and its load-to-bus mapping are compatible with the case study.

**Important distinction:** `04_HGD_for_PF_Py` contains exports supporting a power-flow workflow, not proof that a completed AC power flow has been performed. `05_Power_Flow_Xlsx` is used for optional PF-derived constraints. The separate Module 05 implementation is **not** included in this four-notebook distribution; providing pre-generated Kerber blueprints does not imply that AC power-flow analysis is performed by Module 04.

## File management for users

Keep required intermediate outputs accessible until downstream modules have consumed them. The Module 04 output hierarchy is determined by experiment and run configuration; use `HAGRID_run_manifest.csv` or `.xlsx` to locate a saved run rather than reconstructing directory names by hand.

Large generated results may be excluded from the repository. In such cases, they must be regenerated from the necessary inputs before using downstream analysis or comparison stages. Directory names should not be changed without updating the associated notebook paths.
