DESCRIPTION OF HAGRID (Household Activity-based Grid-aware Residential Integrated Demand model) TOOL

=====================================
	A) TOOL STRUCTURE
=====================================

	The tool is composed by 4 modules, to be run sequentially (the first time) to recreate the case study of interest and then, once the outputs are generated by each module, they can operate independently. They are subdivided as follows:

	(i) MODULE 01 --> synthetic individual activity profile generation, starting from Time-Use Surveys, it reconstructs Weekly 10-min resolution activity profiles for different classes of individual. The classification follows the original Italian TUS dataset, provided in the folder

	(ii) MODULE 02 --> starting from individual profiles, it combines them to generate household activity profiles and linking conventional consumptions (i.e., appliances, lighting) to the corresponding occurring activity

	(iii) MODULE 03 --> from the same household activity profiles, additional electrified loads are calculated, depending on behavioral habits of household members. It calculates: space heating and cooling demands, cooking demand, domestic hot water (DHW) demand and electricity needs for electric vehicle charge at home

	(iv) MODULE 04 --> starting from activity and energy consumption profiles of the previous modules, it evaluates a residential local energy system by solving an operation optimization, after reconstructing the structure of the Low-Voltage distribution grid structure of the tested case study. In a simplified grid-aware constraint perspective, it solves the optimization problem by considering distribution line capacity constraints and the energy demand previously calculated. It returns the minimum system operating cost of the local energy system, keeping track of the single households economic properties too



=====================================
	B) DIRECTORY STRUCTURE
=====================================

The structure of the directory should be mantained as close as possible to the current one, otherwise it needs to be updated within the Module code structure.

It is mainly divided in "input" and "output" folders, each of then furtherly divided into subfolders with information related to each Module.

Main outputs are provided in .xlsx form for an immediate readibility, while Python-based format are preferred (e.g., .pkl) for large datasets that have to be read by other modules.

Each subfolder typically distinguish between "Xls" files (summaries, timeseries, final energy demands), "Pic" (Pictures/graphs), or "Py" files (for large datasets, e.g., as the outputs of the operation optimization problem)



=====================================
	C) TOOL ENVIRONMENT
=====================================

The tool is written in Python and therefore uses Python packages. The code is designed as Jupyther Notebook files (.jpnb) and were tested using Microsoft VisualStudioCode. Please refer to

	https://code.visualstudio.com/

For the VisualStudioCode documentation


An environment including all the required Python packages and oemof.solph packages is presented. oemof.solph is the framework which is used to build and solve the operation optimization problem of a residential local energy system. Please refer to 

	https://oemof-solph.readthedocs.io/en/v0.5.7/index.html

For further documentation about the oemof.solph modeling framework.
