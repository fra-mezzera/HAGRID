# HAGRID

**HAGRID** stands for **Household Activity-based Grid-aware Residential Integrated Demand model**.

HAGRID is a notebook-based Python tool for modelling residential local energy systems. It combines activity-based demand reconstruction, household-level electricity demand profiling, additional electrified loads, and local energy system operation optimization with simplified low-voltage grid-aware constraints.

The tool is associated with a scientific manuscript currently under submission. Full citation details for the related article will be added once available.

## Tool structure

The tool is composed of four main modules, implemented as Jupyter Notebook files. The modules are designed to be run sequentially, especially when recreating a full case study from the initial input data. Once the intermediate outputs have been generated, some modules can also be run independently, depending on the available input/output files.

### Module 01 — Individual activity profile generation

`MODULE_01_individual_activity_profiles.ipynb`

This module generates synthetic individual activity profiles starting from Time-Use Survey data. It reconstructs weekly activity profiles at 10-minute resolution for different classes of individuals. The classification follows the structure of the original Italian Time-Use Survey dataset provided in the input folder.

### Module 02 — Household profiles and conventional loads

`MODULE_02_households_profiles_and_conventional_loads.ipynb`

This module combines individual activity profiles to generate household activity profiles. It then links conventional electricity consumption, such as appliances and lighting, to the corresponding activities occurring within each household.

### Module 03 — Additional electrified loads

`MODULE_03_additional_loads.ipynb`

This module calculates additional electrified loads from the household activity profiles, depending on the behavioural habits of household members. It estimates electricity demand related to space heating, space cooling, cooking, domestic hot water, and electric vehicle charging.

### Module 04 — Local energy system modelling

`MODULE_04_local_energy_system_modeling.ipynb`

This module uses the activity and electricity demand profiles generated by the previous modules to model a residential local energy system. It reconstructs a simplified low-voltage distribution grid structure for the tested case study and solves an operation optimization problem.

The optimization problem considers local energy system operation, distribution line capacity constraints, and the previously calculated energy demand profiles. The module returns the minimum operating cost of the local energy system while also tracking household-level economic indicators.

## Recommended workflow

The notebooks should be run in the following order:

```text
MODULE_01_individual_activity_profiles.ipynb
MODULE_02_households_profiles_and_conventional_loads.ipynb
MODULE_03_additional_loads.ipynb
MODULE_04_local_energy_system_modeling.ipynb
```

Some outputs generated by one module are used as inputs by the following modules. Therefore, the current directory structure should be preserved when running the tool.

## Directory structure

The repository is mainly organized into two main folders:

```text
input/
output/
```

The `input/` folder contains the input files required by the different modules.

The `output/` folder contains intermediate outputs, example outputs, figures, tables, and data files generated by the modules. Some of these outputs are required by subsequent modules and should not be removed unless the corresponding previous module is re-run.

Additional README files are included inside the subfolders to describe their specific contents.

The output folders typically distinguish between:

```text
Xls/ or *_Xls/    tabular outputs, summaries, time series and final energy demand files
Pics/ or *_Pics/  figures, graphs and visual outputs
Py/ or *_Py/      Python-readable files and larger intermediate datasets
```

Main outputs are often provided in `.xlsx` format for immediate readability. Python-based formats, such as `.pkl`, `.pkl.gz`, `.npy` or `.json`, are used for larger datasets or files that need to be read by other modules.

## Installation

The tool is written in Python and is designed to be run through Jupyter Notebooks. It was developed and tested using Microsoft Visual Studio Code.

The Python environment used for the notebooks can be recreated from:

```text
environment.yml
```

Using conda:

```bash
conda env create -f environment.yml
conda activate hagrid
```

Then open the repository folder in Visual Studio Code and select the corresponding Python environment as the notebook kernel.

If the environment name in `environment.yml` is different from `hagrid`, activate the environment using the name specified in the file.

## Main dependencies

The tool uses Python packages for data processing, plotting and optimization. The local energy system operation optimization is built using `oemof.solph`.

For additional documentation, please refer to:

* Visual Studio Code: https://code.visualstudio.com/
* oemof.solph: https://oemof-solph.readthedocs.io/

## Reproducibility notes

The notebooks rely on relative paths and on the repository folder structure. Users should keep the directory structure unchanged unless the paths are also updated within the module code.

Some files in the `output/` folder are not only final results, but also intermediate files required by later modules. If these files are deleted or modified, the previous modules should be re-run before executing the following ones.
